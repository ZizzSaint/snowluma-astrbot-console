把 AstrBot 接入 QQ（SnowLuma + AstrBot 桥接）

SnowLuma 负责把本机 QQ 变成 OneBot v11 机器人；AstrBot 内置 OneBot v11（aiocqhttp）适配器，作为反向 WebSocket 服务端监听。因此由 SnowLuma 主动连接 AstrBot，连接地址形如 ws://127.0.0.1:6199/ws。

手机 QQ 扫码 → 本机 QQ（NTQQ） → SnowLuma
OneBot v11 反向 WS
ws://127.0.0.1:6199/ws AstrBot
aiocqhttp 适配器 → 大模型 / 插件

适用条件

    一键桥接

    详细步骤

    1. 准备好本机 QQ

      确保装了桌面版 QQ（NTQQ）并能正常打开。SnowLuma 通过注入 QQ.exe 进程来接管登录，所以 QQ 必须是桌面版，且与 SnowLuma 运行在同一个 Windows 用户下（权限要一致，不要一个用管理员、一个不用）。

    2. 在本应用里启动 SnowLuma

      回到「总览」→ SnowLuma 卡片 → 点击「启动」。本应用会自动开启 hook 自动注入（hookAutoLoad），启动后自动注入已经打开的 QQ 进程；如果 QQ 后开，SnowLuma 会持续探测并注入。

    3. 用手机 QQ 扫码登录

      打开「SnowLuma 控制台」标签页，用 admin + 应用里显示的初始密码登录（首次启动时由启动器预置，可在工具栏「登录凭据」里复制）。然后在弹出的 QQ 窗口里用手机扫码登录。

    4. 启动 AstrBot 并登录面板

      「总览」→ AstrBot 卡片 → 「启动」。打开「AstrBot 控制台」，用户名 astrbot，初始密码可在工具栏「登录凭据」里复制（若密码丢失，用「设置 → 重置 AstrBot 面板密码」重新生成）。

    5. 一键写入两边配置

      点击上方「一键完成」：启动器会把 AstrBot 的 OneBot v11 平台配置写成反向 WS（127.0.0.1:6199）并重启 AstrBot，然后把 SnowLuma 的 config/onebot.json 写入一个指向 ws://127.0.0.1:6199/ws 的反向 WS 客户端。

    6. 验证

      AstrBot 日志出现 aiocqhttp(OneBot v11) 适配器已连接。 即成功。用另一个 QQ 号（或群里）给机器人发 /help（默认唤醒前缀 /），能收到回复就说明整条链路通了。

    手动配置（排错用）

    SnowLuma 侧

    WebUI → 「配置 / OneBot」→ 反向 WS（wsClients）新增一条：

    名称: astrbot-bridge
启用: 是
URL: ws://127.0.0.1:6199/ws
Role: Universal
Access Token: 与 AstrBot 一致（可留空）

    AstrBot 侧

    WebUI → 「机器人」→ 创建/编辑 → 选 OneBot v11 → 接入设置：

    反向 Websocket 主机: 127.0.0.1
反向 Websocket 端口: 6199
Token: 与 SnowLuma 一致（可留空）

    常见问题

    • 端口 6199 被占用：改成一个空闲端口，然后两边的端口保持一致（本应用「设置 → 端口」也能改）。
    • 一直显示未连接：先确认 SnowLuma 里 QQ 已登录成功（SnowLuma 控制台能看到账号），再确认 AstrBot 已重启并加载了 OneBot v11 平台。
    • hook 注入失败 / QQ 崩溃：SnowLuma 的 native hook 与 QQ 版本绑定。QQ 自动更新到新版本后可能不再兼容——官方建议冻结 QQ 自动更新（设置页有一键冻结），或在设置里切换到其他 SnowLuma 版本重试。
    • QQ 窗口没弹出来：SnowLuma 只注入，不会隐藏 QQ；请手动打开一次 QQ 再扫码。
    • 机器人不回复：AstrBot 还需要配置模型提供商（服务提供商 API Key），否则收到消息也不会生成回复。
